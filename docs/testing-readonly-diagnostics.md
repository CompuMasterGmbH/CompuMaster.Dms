# Read-only CI diagnosis

The manual `read_only_diagnostics` input of Build and Test is an optional diagnosis path. It runs only the Windows Scopevisio and ownCloud partitions, sequentially under the same existing account concurrency groups as normal integration tests. The default is false; normal CI retains full Windows/net8 coverage and configured other-platform samples and explicitly excludes the separate diagnostic fixtures. Native-only verification and read-only diagnosis cannot be selected together.

The ecosystem coordinator must first confirm that all old resource-modifying test execution and cleanup is terminal and establish a separate exclusive window covering local sessions and other repositories. GitHub account groups do not provide that cross-repository/local coordination. Supply the confirmed offset-bearing ISO8601 end through `diagnostic_window_until`. Each job and fixture requires explicit CI-only admission with at least twenty minutes remaining; the selected jobs have a twenty-minute timeout. Missing secrets fail admission before Settings adapters can read local profiles or prompt for credentials. Neither the input nor a successful isolated guard test grants server access.

The fixtures authenticate and perform metadata reads only. They have no mutating setup/teardown and never create, rename, delete, trash or retry uncertain resource writes. ownCloud reports the internal fixed discovery outcome/phase, failure category and optional numeric HTTP status and still fails when required sharing is unavailable. Scopevisio reads collections and only the fixed historical copy and unchanged fixture parents described below, without creating them. It prints at most twenty strictly matched CollectionMove GUID candidate names, rather than unrelated collection/user data.

The optional `diagnostic_temporary_name` input accepts exactly `.compumaster-dms-` followed by 32 lowercase hexadecimal digits, or an empty value. It is passed only through an environment variable and is validated before authentication; paths, prefixes, whitespace, control characters and trailing segments are rejected without printing the input. No historical value is embedded in source. Existing CI, expiry, secret admission, account concurrency groups and matrix serialization remain unchanged.

The historical inspector selects only `ZZZ_UnitTests_Dms_TestFolder` and its immediate `copy-sub-target`, plus `ZZZ_UnitTests_CM.Dms`, `Folder` and `Folder/Sub` (the unknown first duplicate upload's source parent). It rejects root/folder collisions and changed identity or inconsistent folder placement before reading descendants. The existing collection inventory is used for exact ordinal root selection, not a global document search. Folder metadata requests are constrained to the selected collection and immediate parent, with only identity/name/parent fields; document GET requests use that exact collection/parent, offset zero and 21 rows. At most 20 document records per parent are observed. No pagination, recursion, trash/orphan/global search, prefix selection or additional metadata/content fetch is performed.

Output includes stable SHA-256 fingerprints of the authenticated user, configured account, selected tenant and observed resource/owner/uploader identities, rather than raw identities. These fingerprints support correlation only; they do not establish that the configured account owns a resource. It reports exact source/target/optional-witness matches, collisions, bounded page completeness and visible/hidden collection and folder reference counts. Missing reference metadata stays unconfirmed; a seven-byte size is only a size observation, not a content or ownership match. Content is not read because the bounded metadata inventory does not require it. The copy fixture's immutable seven bytes do not authorize downloading or deleting uncertain candidates.

Missing roots/folders stop descendant reads. A missing exact file is reported as indexed absence only when the bounded page is complete; truncated or incomplete pages cannot establish even indexed absence. Every result keeps global/trash/orphan absence unverified. The unknown duplicate suffix remains unresolved; its first upload's HTTP500 cannot establish commitment or absence. The original copy error reported the temporary parent under `copy-sub-target`; the shared loop callsite cannot establish the iteration, and loop/SDK-parent consistency remains unresolved. No inventory observation supplies cleanup authority.

Candidates are not proof of current-run ownership. The failed historical rename artifact does not preserve its source GUID; an empty candidate inventory does not establish historical exact owned absence, trash absence or complete cleanup. Any recovery requires separate ownership evidence and a new coordinator grant. Authentication/read failures produce fixed phase/category/numeric status only; raw exceptions, bodies, headers, URLs and identities are not included. JUnit and TRX results retain the selected diagnostics separately from historical failures.

This Windows-only selected run is not real-server round-trip acceptance, a native acceptance run, the complete twelve-job matrix or a publication prerequisite substitute. Diagnose and fix only an established defect, independently review/merge it, then run the mandatory final merged-head Windows/net8-full and other-platform-sample pipeline with the documented published dependency set. Workflow source edits may reactivate previously held workflows; the coordinator audits and restores the holds before any subsequent manual dispatch.

Offline verification consists of `test-readonly-diagnostic-configuration.ps1`, `test-test-level-configuration.ps1` and the isolated `ReadOnlyServerDiagnosticTest`, `HistoricalReadOnlyPreflightTest` and partition tests. These checks neither execute a diagnostic fixture nor read profiles, authenticate or access a remote server.
