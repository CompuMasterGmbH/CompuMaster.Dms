# Read-only CI diagnosis

The manual `read_only_diagnostics` input of Build and Test is an optional diagnosis path. It runs only the Windows Scopevisio and ownCloud partitions, sequentially under the same existing account concurrency groups as normal integration tests. The default is false; normal CI retains its complete configured matrix and explicitly excludes the separate diagnostic fixtures. Native-only verification and read-only diagnosis cannot be selected together.

The ecosystem coordinator must first confirm that all old resource-modifying test execution and cleanup is terminal and establish a separate exclusive window covering local sessions and other repositories. GitHub account groups do not provide that cross-repository/local coordination. Supply the confirmed offset-bearing ISO8601 end through `diagnostic_window_until`. Each job and fixture requires explicit CI-only admission with at least twenty minutes remaining; the selected jobs have a twenty-minute timeout. Missing secrets fail admission before Settings adapters can read local profiles or prompt for credentials. Neither the input nor a successful isolated guard test grants server access.

The fixtures authenticate and perform metadata reads only. They have no mutating setup/teardown and never create, rename, delete, trash or retry uncertain resource writes. ownCloud reports the internal fixed discovery outcome/phase, failure category and optional numeric HTTP status and still fails when required sharing is unavailable. Scopevisio reads collections and reports presence of the existing fixture root/folder without creating them. It prints at most twenty strictly matched CollectionMove GUID candidate names, rather than unrelated collection/user data.

Candidates are not proof of current-run ownership. The failed historical rename artifact does not preserve its source GUID; an empty candidate inventory does not establish historical exact owned absence, trash absence or complete cleanup. Any recovery requires separate ownership evidence and a new coordinator grant. Authentication/read failures produce fixed phase/category/numeric status only; raw exceptions, bodies, headers, URLs and identities are not included. JUnit and TRX results retain the selected diagnostics separately from historical failures.

This Windows-only selected run is not real-server round-trip acceptance, a native acceptance run, the complete twelve-job matrix or a publication prerequisite substitute. Diagnose and fix only an established defect, independently review/merge it, then run the mandatory full final merged-head matrix with the documented published dependency set. Workflow source edits may reactivate previously held workflows; the coordinator audits and restores the holds before any subsequent manual dispatch.

Offline verification consists of `test-readonly-diagnostic-configuration.ps1`, `test-test-level-configuration.ps1` and the isolated `ReadOnlyServerDiagnosticTest`/partition tests. These checks neither execute a diagnostic fixture nor read profiles, authenticate or access a remote server.
