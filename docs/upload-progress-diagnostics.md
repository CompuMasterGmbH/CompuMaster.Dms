# Upload progress diagnostics

BrowserUI distinguishes local selection/size planning, remote-folder preparation, starting a provider transfer, reported source processing and pending server confirmation. Remote folder preparation reports completed directory counts and does not announce file 1 prematurely. The file estimate is accompanied by a separate batch rate and estimate. Planned local sizes supply unstarted-file totals; provider-reported totals take precedence. Missing sizes, missing samples and pending confirmation have explicit unknown explanations. A new attempt excludes bytes completed in an earlier attempt from its throughput denominator.

Optional System.Diagnostics.Trace output records scalar phase timings: local size-planning duration, remote-folder duration and logical lookup/create calls, first reported source byte, first reported Finalizing phase, awaited provider-call wall duration and terminal outcome. Records contain provider type and file ordinal, without file paths, resource IDs, credentials or response bodies. Source reports describe transport-consumed bytes; they do not prove remote receipt. Awaited call wall time includes scheduling/continuation delay. Logical folder calls are not HTTP request counts. Protocol metadata/admission requests, actual wire throughput and direct-transfer comparisons still require a coordinated provider/SDK investigation on the real systems.

The progress list retains its rows and selection. Counter-only snapshots do not rebuild or measure all captions. A durable 266-file/1,000-update test requires only one additional row measurement after its state changes, rather than repeated measurement of the entire batch. This verifies reduced redundant UI work; it does not establish the cause of the reported server throughput.
