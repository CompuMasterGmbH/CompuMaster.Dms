# Browser upload and drag regressions

The follow-up to #109/#84 and #107/#108 addresses #110–#114 in `CompuMaster.Dms.BrowserUI`. Selected replacement also adds a compatible API to `CompuMaster.Dms.Providers`; dependency package pins stay unchanged.

- Inline tree editing uses the existing remote rename command. Every browser root rejects mouse, F2 and programmatic edit entry; permissions and source identity are checked again before a write. The native control cannot commit an unconfirmed cosmetic label. A confirmed refresh reloads descendant paths.
- Upload refresh captures selection, expanded branches and viewport anchors using resource identifiers within their parent lineage, falling back to paths when identifiers are unavailable. Missing or ambiguous resources fall back to the nearest surviving ancestor. A separate drop destination does not replace the original selection.
- All local file/folder upload entry points share an operation-scoped conflict policy: Yes, Yes to all, No, No to all and Cancel. Skipped files have a distinct terminal state and no payload bytes. Retry/continue retains decisions and completed/skipped files. Existing directories are merged without file-conflict prompts; ambiguous directory/file paths fail clearly.
- `BaseDmsProvider.ReplaceFileWithProgressAsync` replaces a selected existing file. Unique-path providers preserve their existing upload override. Providers allowing duplicate names must implement an identity-bound replacement or receive a clear unsupported-operation error. CenterDevice/Scopevisio validates the selected document's parent membership and uses that exact document for a new version, preserving local modification time, progress and parent-cache invalidation. Published SDK methods suffice; no moving SDK import is required. Path-based upload overloads retain their existing semantics. Neither preflight nor replacement introduces an atomic server-side path/version precondition.
- Internal file-list drags carry only an ephemeral opaque token across OLE. Provider, instance, scope and selected resource identifiers remain in the originating browser. Only a validated tree node in that browser can accept Move; the backend action starts after the native Drop callback returns. Same-folder drops, stale contexts and duplicate source identities are rejected. Failure refresh preserves completed moves and the original diagnostic.
- Explorer downloads remain virtual copies. Move-only permission exposes no shell file descriptors or contents. Native Move feedback/release is rejected outside an approved internal target; the preferred shell effect remains Copy.
- Root-file restrictions use `BrowseInRootFolderName` and `SupportsFilesInRootFolder`, rather than the visible node's position. A mixed selection containing forbidden loose files is rejected before writes. Supported folder trees and ordinary scoped roots remain eligible. Capability, identity and permission gates are repeated before directory creation and payload writes.

Isolated Windows tests cover native label events/F2, selection refresh, conflict/recovery decisions, identity-bound replacement using the second same-name document, native virtual-file Copy targets, internal move routing/partial failures and root upload gates. Tests use fake providers, `.invalid` handlers or owned temporary local paths; they do not establish real-server acceptance. The net48 BrowserUI run uses a filtered harness compiling the checked-in test sources against the same production project.

The workstation GUI notice holds `Local\CompuMaster.Dms.WorkstationGuiTests` before its countdown and through cleanup. Busy acquisition fails before opening test windows. Legacy/ad hoc launchers can hold the same mutex around an unchanged host; do not acquire it both in a launcher and the updated notice host. This lease is separate from remote-server reservations. The scoped UI dispatcher captures window-callback exceptions as test failures instead of opening the runtime exception dialog.

Remaining acceptance uses owned remote folders in a coordinated server window: physical Explorer gestures on WebDAV/Scopevisio, actual organisation A/B navigation, slow-click/F2 rename, post-success-dialog tree selection, conflict prompts and version/replace results, internal moves including partial failures, and true/scoped root drops. Check cleanup, exact package/build/runtime and existing integration reservations before each run. #108 additionally requires HTTP/admission profiling and a direct-transfer baseline after the owning SDK API work; UI and logical-call timings do not establish wire throughput.
